Executive Summary
HTUAI is a comprehensive academic management platform for HTU students that combines degree progress tracking with semester planning, GPA calculation, study analytics, and gamification. This document contains all product, design, and performance specifications required to implement the "Semester Planner & GPA" module alongside the existing "Course Tracker" system.
Key objectives:
	Automate repetitive semester setup workflows
	Provide accurate GPA/CGPA tracking using HTU's official grading system
	Sync academic schedules with Google Calendar
	Motivate consistent study habits through gamification
	Enable admin monitoring of system health and usage

PART 1: PRODUCT SPECIFICATIONS
1.1 Product Overview
1.1.1 HTUAI Current State (v1)
HTUAI currently provides:
	Degree progress dashboard: Total credits (completed/required), courses completed, overall completion percentage
	Academic status labels: Based on completion percentage (e.g., "ACADEMIC ASPIRANT")
	Requirement breakdown: University Requirements, University Elective, College Requirements, Department Requirements, Department Elective
	Curriculum view: 4-year roadmap organized by levels (Level 1–4) with prerequisite tracking
	Course details: Name, code, credit hours, provider tags (HTU, HNC, HND, UE-I/II/III), prerequisites
Authentication displays HTU ID and major in header with sign-out capability.
1.1.2 New Module: Semester Planner & GPA
The new module adds per-student semester management:
	Semester organization: Winter (Oct–Feb), Spring (Mar–Jun), Summer (Jul–Sep)
	GPA tracking: Per-semester GPA and cumulative GPA using HTU grading rules
	Study analytics: Session logging, time tracking per course
	In-app notes: Rich text editor with Notion-like experience
	Calendar integration: Google Calendar sync for classes, exams, deadlines
	Gamification: XP, levels, streaks, quests, badges
	Admin dashboard: Usage monitoring, error tracking, analytics
1.1.3 Clear Separation of Concerns
Course Tracker (existing):
	Purpose: Show degree requirements and curriculum
	Data: Static curriculum definitions, prerequisite rules
	Scope: Program-level view
Planner & GPA (new):
	Purpose: Manage student's actual semesters, grades, study behavior
	Data: Per-student instances of semesters, courses, grades, notes
	Scope: Student-level personalized tracking
Critical rule: Planner cannot edit curriculum definitions; it only tracks student progress against them.

1.3 Domain Model & Data Structures
1.3.1 Core Entities
All entities use UUID for id. All have created_at and updated_at timestamps (UTC).
User
	id (UUID, primary key)
	email (string, unique)
	name (string, nullable)
	htu_id (string, nullable) – HTU student ID
	role (enum: student | admin)
	created_at, updated_at
Relationships: Has many Semesters, StudySessions, GPAHistory, Integrations, CalendarEvents, Quests, UserBadges; has one GamificationProfile.
Semester
	id (UUID)
	user_id (UUID, foreign key → User)
	type (enum: winter | spring | summer)
	year (integer, e.g., 2025)
	name (string, e.g., "Winter 2025")
	start_date (date)
	end_date (date)
	semester_gpa (float, nullable)
	created_at, updated_at
Relationships: Belongs to User; has many Courses, GPAHistory entries.
Course
	id (UUID)
	semester_id (UUID, foreign key → Semester)
	name (string)
	code (string) – REAL HTU COURSE CODE (e.g., CS101, MATH202), never auto-generated
	credits (float)
	instructor_name (string, nullable)
	location (string, nullable)
	class_schedule (JSON, nullable) – Structure: { days: ["Sunday", "Tuesday"], start_time: "09:00", end_time: "10:30" }
	status (enum: planned | in_progress | completed | dropped)
	grade_letter (enum: D | M | P | U | null)
	grade_point (float, nullable) – Derived from grade_letter using HTU rules
	final_mark (float, nullable) – Numeric score if available
	is_completed (boolean, default false)
	created_at, updated_at
Relationships: Belongs to Semester; has one CourseNote; has many StudySessions, CalendarEvents.
CourseNote
	id (UUID)
	course_id (UUID, foreign key → Course, unique)
	content (JSON) – Rich text editor state (Lexical/Tiptap format)
	created_at, updated_at
Relationships: Belongs to Course (one-to-one).
StudySession
	id (UUID)
	user_id (UUID, foreign key → User)
	course_id (UUID, foreign key → Course)
	date (datetime)
	duration_minutes (integer)
	type (enum: reading | practice | project | review | other)
	notes (string, nullable) – Short description
	created_at
Relationships: Belongs to User and Course.
GPAHistory
	id (UUID)
	user_id (UUID, foreign key → User)
	semester_id (UUID, foreign key → Semester, nullable)
	semester_gpa (float, nullable)

	refresh_token (string, encrypted, nullable)
	expires_at (datetime, nullable)
	metadata (JSON, nullable) – Calendar ID, timezone, etc.
	created_at, updated_at
Relationships: Belongs to User.
CalendarEvent
	id (UUID)
	user_id (UUID, foreign key → User)
	course_id (UUID, foreign key → Course, nullable)
	type (enum: class | midterm | final | assignment_due | other)
	google_event_id (string, nullable) – For update operations
	title (string)
	start_datetime (datetime)
	end_datetime (datetime)
	created_at, updated_at
Relationships: Belongs to User; optionally belongs to Course.
GamificationProfile
	id (UUID)
	user_id (UUID, foreign key → User, unique)
	xp (integer, default 0)

	current_streak_days (integer, default 0)

Relationships: Belongs to User (one-to-one).
Badge
	id (UUID)
	code (string, unique) – e.g., TRANSCRIPT_MASTER, GPA_UP

	description (string)
	icon (string, nullable) – Icon identifier or emoji

UserBadge
	id (UUID)

	badge_id (UUID, foreign key → Badge)

Relationships: Belongs to User and Badge.
Quest

1.4 HTU Grading & GPA Rules (Non-Negotiable)
1.4.1 Grade Mapping
Per-course grades map to grade points:
	D (Distinction) → 4.0
	M (Merit) → 3.2
	P (Pass) → 2.4
	U (Unclassified) → 0.0 (for GPA calculation purposes)
1.4.2 Passing Requirements
	Minimum passing grade per course: P (2.4)
	Minimum cumulative average: P (2.4)
1.4.3 Classification Ranges (Cumulative GPA)
	3.6–4.0 → Excellent (EX)
	3.2–3.59 → Very Good (VG)
	2.8–3.19 → Good
	2.4–2.79 → Satisfactory
	<2.4 → Unclassified
1.4.4 Semester Types & Date Ranges
	Winter: October 1 – February 28/29
	Spring: March 1 – June 30
	Summer: July 1 – September 30
1.4.5 GPA Calculation Formulas
Semester GPA:
"Semester GPA"=(∑▒ ("credits" ×"grade point" ))/(∑▒  "credits" )
Where only completed courses with valid grade points are included.
Cumulative GPA (CGPA):
"CGPA"=(∑_"all completed courses" ▒  ("credits" ×"grade point" ))/(∑_"all completed courses" ▒  "credits" )
Implementation requirements:
	Round GPA to 2 decimal places
	Return null if no completed courses exist
	Never use magic numbers; reference HTU grade constants
Example calculation:
Courses in Winter 2025:
	CS101 (3 credits, grade M = 3.2)
	MATH102 (3 credits, grade D = 4.0)
	ENG101 (2 credits, grade P = 2.4)
"Semester GPA"=((3×3.2)+(3×4.0)+(2×2.4))/(3+3+2)=(9.6+12.0+4.8)/8=26.4/8=3.30
Classification: Very Good (VG) (falls in 3.2–3.59 range)

1.5 Feature Requirements (Functional)
FR-1: Semester Management
	FR-1.1: User can create semesters with type (winter/spring/summer) and year
	FR-1.2: System enforces semester date ranges based on type
	FR-1.3: User can view all past, current, and planned semesters
	FR-1.4: On first use, wizard guides user to enter current semester and optionally past semesters for CGPA baseline
FR-2: Course Management
	FR-2.1: User can add courses to any semester with: name, code (real HTU code), credits, instructor, location, schedule
	FR-2.2: Course codes must be real HTU course codes, never auto-generated
	FR-2.3: User can mark courses as planned/in progress/completed/dropped
	FR-2.4: User can enter grade letter (D/M/P/U) for completed courses
	FR-2.5: System derives grade point from grade letter using HTU mapping
	FR-2.6: User can optionally enter final numeric mark
FR-3: GPA Calculation & Display
	FR-3.1: System automatically calculates semester GPA when at least one course in semester has a grade
	FR-3.2: System calculates CGPA across all completed courses from all semesters
	FR-3.3: System assigns classification (EX/VG/Good/Satisfactory/Unclassified) based on CGPA
	FR-3.4: System creates GPAHistory snapshots on grade changes
	FR-3.5: Dashboard displays current CGPA, classification, and GPA trend
FR-4: Study Session Logging
	FR-4.1: User can log study sessions with: course, date, duration (minutes), type, optional notes
	FR-4.2: System aggregates total study time per course and per semester
	FR-4.3: Dashboard displays study statistics and weekly summaries
FR-5: Rich Text Notes
	FR-5.1: Each course has a dedicated notes area with rich text editing
	FR-5.2: Notes support: headings, bold/italic, lists, checklists, colored highlights, callouts
	FR-5.3: Notes auto-save on blur or every 3 seconds of idle
	FR-5.4: Notes are stored as structured JSON (editor state)
	FR-5.5: Notes editor is full-page on mobile, premium appearance similar to Notion
FR-6: Google Calendar Integration
	FR-6.1: User can connect Google account via OAuth in Settings
	FR-6.2: System stores access token, refresh token securely (encrypted at rest)
	FR-6.3: System creates Google Calendar events for:
	Class schedules (if provided)
	Midterm exam dates
	Final exam dates
	Assignment deadlines (if tracked)
	FR-6.4: When dates change in HTUAI, system updates corresponding Google Calendar event (not recreate)
	FR-6.5: Integration is one-way: HTUAI → Google Calendar only
	FR-6.6: User can disconnect integration and remove synced events
FR-7: Gamification System
XP & Levels
	FR-7.1: User earns XP for:
	Logging study sessions: 1 XP per minute (max 100 XP/day from study)
	Completing a course: 150 XP
	Improving semester GPA vs previous: 200 XP
	Opening planner dashboard daily (once): 10 XP
	FR-7.2: Level calculated as: level = floor(xp / 500) + 1
	FR-7.3: Dashboard displays XP bar with progress to next level
Streaks
	FR-7.4: Study streak tracks consecutive days with ≥1 study session
	FR-7.5: Planner streak tracks consecutive days visiting planner
	FR-7.6: Nightly job evaluates streaks; resets to 0 if no activity that day
	FR-7.7: Dashboard displays current streak and longest streak
Quests
	FR-7.8: System auto-generates quests:
	Course-level: "Reach at least P (2.4)", "Improve from P to M or D"
	Semester-level: "Raise CGPA by 0.1", "Study 5 days this week"
	FR-7.9: Quest progress updates automatically based on user actions
	FR-7.10: Completed quests award bonus XP
	FR-7.11: Dashboard shows 2–3 active quests with progress bars
Badges
	FR-7.12: Predefined badges:
	TRANSCRIPT_MASTER: Entered all past semesters with courses
	GPA_UP: CGPA increased compared to previous semester
	CONSISTENT_STUDY_5: Maintained 5-day study streak
	COURSE_RESCUE: Improved course from U to P or higher
	FR-7.13: System awards badges automatically when conditions met
	FR-7.14: Visual notification shown on badge unlock
FR-8: Admin Dashboard
	FR-8.1: Admin users can view:
	Total registered students
	Active users (daily, weekly)
	Average CGPA by semester type
	Average study hours per week
	Integration connection rates
	Recent errors and sync failures
	FR-8.2: Admin can filter logs by date range and type
	FR-8.3: Charts display usage trends and system health

1.6 Non-Functional Requirements

	NFR-1.1: First Contentful Paint < 2 seconds on 4G mobile connection
	NFR-1.2: Planner dashboard API response < 300ms for 10 semesters, 60 courses
	NFR-1.3: GPA calculation completes in < 50ms for 100 courses
	NFR-1.4: Notes auto-save without blocking user input

	NFR-2.1: Calendar sync failures retry 3 times with exponential backoff

	NFR-3.1: All API communication via HTTPS
	NFR-3.2: Integration tokens encrypted at rest (AES-256)
	NFR-3.3: JWT tokens for user authentication with 7-day expiry
	NFR-3.4: Rate limiting on all API endpoints (100 req/min per user)
NFR-4: Usability
	NFR-4.1: Onboarding wizard completable in < 5 minutes
	NFR-4.2: All interactive elements have ≥44px tap targets on mobile
	NFR-4.3: Error messages actionable and user-friendly
	NFR-4.4: Zero data loss on network interruption (draft saving)
NFR-5: Accessibility
	NFR-5.1: WCAG 2.1 AA compliance minimum
	NFR-5.2: Keyboard navigation support for all features
	NFR-5.3: Color contrast ratios ≥4.5:1 for text

NFR-6: Scalability

PART 2: DESIGN SPECIFICATIONS
2.1 UX Principles (Mobile-First)
2.1.1 Mobile-First Philosophy
	Primary design target: Mobile devices (320–430px width)
	Design process: Start with mobile layout, progressively enhance for tablet/desktop
	Core principle: Essential content and actions visible without scrolling or horizontal scroll
2.1.2 Responsive Breakpoints
	Mobile: 320–767px (single column, stacked)
	Tablet: 768–1023px (2 columns where appropriate)
	Desktop: 1024px+ (3–4 columns, sidebars)
2.1.3 Touch & Interaction
	Minimum tap target: 44×44px
	Primary actions: Bottom-fixed or prominently placed buttons
	Swipe gestures: Optional enhancements, not required for core functionality
	Loading states: Skeleton screens, not spinners alone
	Haptic feedback: Optional on important actions (if PWA supports)
2.1.4 Content Priority
Mobile screens show (in order):
	Header/navigation
	Key metrics/stats
	Primary action
	Content list/detail
	Secondary actions
Less important content hidden behind tabs, accordions, or "Show more".
2.1.5 Typography & Readability
	Base font size: 16px minimum on mobile
	Line height: 1.5–1.6 for body text
	Heading scale: H1 (28–32px), H2 (24–28px), H3 (20–24px) on mobile
	Content width: Max 65ch for text blocks even on desktop for readability

3.1 Architecture Overview
3.1.1 System Architecture
Layers:
	Frontend (Client)
	Next.js 14 with App Router
	Runs in user's browser
	Communicates with backend via REST API
	Backend (API Server)
	Node.js 20 with NestJS framework
	Handles business logic, GPA calculations, gamification
	Manages Google Calendar integration
	Serves REST endpoints
	Database

import { Injectable } from '@nestjs/common';
import {
HTU_GRADE_POINTS,
CLASSIFICATION_RANGES,
Classification,
GradeLetter,
} from './gpa.constants';
export interface CourseForGPA {
credits: number;
gradePoint: number;
}
@Injectable()
export class GpaService {
gradeLetterToPoint(letter: GradeLetter): number {
return HTU_GRADE_POINTS[letter];
}
calculateSemesterGpa(courses: CourseForGPA[]): number | null {
const validCourses = courses.filter(
(c) => c.gradePoint !== null && c.credits > 0,
);
if (validCourses.length === 0) return null;
const totalCredits = validCourses.reduce((sum, c) => sum + c.credits, 0);
const totalPoints = validCourses.reduce(
  (sum, c) => sum + c.credits * c.gradePoint,
  0,
);

return parseFloat((totalPoints / totalCredits).toFixed(2));

}
calculateCumulativeGpa(allCompletedCourses: CourseForGPA[]): number | null {
return this.calculateSemesterGpa(allCompletedCourses);
}
classifyGpa(gpa: number): Classification {
for (const range of CLASSIFICATION_RANGES) {
if (gpa >= range.min && gpa <= range.max) {
return range.classification;
}
}
return 'Unclassified';
}
}

import { Injectable } from '@nestjs/common';
import { PrismaService } from '../prisma/prisma.service';
import { XP_CONFIG, LEVEL_XP_THRESHOLD } from './gamification.constants';
@Injectable()
export class GamificationService {
constructor(private prisma: PrismaService) {}
calculateLevel(xp: number): number {
return Math.floor(xp / LEVEL_XP_THRESHOLD) + 1;
}
async awardXp(userId: string, event: string, value: number): Promise<number> {
let xpAwarded = 0;
switch (event) {
  case 'study_logged':
    const minutes = value;
    xpAwarded = Math.min(
      minutes * XP_CONFIG.studySessionPerMinute,
      XP_CONFIG.studySessionDailyCap,
    );
    break;
  case 'course_completed':
    xpAwarded = XP_CONFIG.courseCompleted;
    break;
  case 'gpa_improved':
    xpAwarded = XP_CONFIG.semesterGpaImproved;
    break;
  case 'daily_open':
    xpAwarded = XP_CONFIG.dailyPlannerOpen;
    break;
}

const profile = await this.prisma.gamificationProfile.upsert({
  where: { userId },
  create: {
    userId,
    xp: xpAwarded,
    level: this.calculateLevel(xpAwarded),
  },
  update: {
    xp: { increment: xpAwarded },
  },
});

const newLevel = this.calculateLevel(profile.xp + xpAwarded);
if (newLevel > profile.level) {
  await this.prisma.gamificationProfile.update({
    where: { userId },
    data: { level: newLevel },
  });
}

return xpAwarded;

}
async updateStreak(userId: string): Promise<void> {
const today = new Date();
today.setHours(0, 0, 0, 0);
const profile = await this.prisma.gamificationProfile.findUnique({
  where: { userId },
});

if (!profile) return;

const lastActivity = profile.lastActivityDate
  ? new Date(profile.lastActivityDate)
  : null;

if (lastActivity) {
  lastActivity.setHours(0, 0, 0, 0);
  const diffDays = Math.floor(
    (today.getTime() - lastActivity.getTime()) / (1000 * 60 * 60 * 24),
  );

  if (diffDays === 1) {
    // Consecutive day
    await this.prisma.gamificationProfile.update({
      where: { userId },
      data: {
        currentStreakDays: { increment: 1 },
        longestStreakDays: Math.max(
          profile.longestStreakDays,
          profile.currentStreakDays + 1,
        ),
        lastActivityDate: today,
      },
    });
  } else if (diffDays > 1) {
    // Streak broken
    await this.prisma.gamificationProfile.update({
      where: { userId },
      data: {
        currentStreakDays: 1,
        lastActivityDate: today,
      },
    });
  }
} else {
  // First activity
  await this.prisma.gamificationProfile.update({
    where: { userId },
    data: {
      currentStreakDays: 1,
      longestStreakDays: 1,
      lastActivityDate: today,
    },
  });
}

}

import { Injectable } from '@nestjs/common';
import { google, calendar_v3 } from 'googleapis';
import { PrismaService } from '../../prisma/prisma.service';
@Injectable()
export class GoogleCalendarService {
private oauth2Client;
constructor(private prisma: PrismaService) {
this.oauth2Client = new google.auth.OAuth2(
process.env.GOOGLE_CLIENT_ID,
process.env.GOOGLE_CLIENT_SECRET,
process.env.GOOGLE_REDIRECT_URI,
);
}
getAuthUrl(): string {
return this.oauth2Client.generateAuthUrl({
access_type: 'offline',
scope: ['https://www.googleapis.com/auth/calendar'],
});
}
async handleCallback(code: string, userId: string): Promise<void> {
const { tokens } = await this.oauth2Client.getToken(code);
await this.prisma.integration.create({
  data: {
    userId,
    type: 'google_calendar',
    accessToken: tokens.access_token, // Encrypt in production
    refreshToken: tokens.refresh_token,
    expiresAt: tokens.expiry_date ? new Date(tokens.expiry_date) : null,
  },
});

}
async createEvent(
userId: string,
event: {
title: string;
startDatetime: Date;
endDatetime: Date;
courseId?: string;
type: string;
},
): Promise<string> {
const integration = await this.prisma.integration.findFirst({
where: { userId, type: 'google_calendar' },
});
if (!integration) throw new Error('Calendar not connected');

this.oauth2Client.setCredentials({
  access_token: integration.accessToken,
  refresh_token: integration.refreshToken,
});

const calendar = google.calendar({ version: 'v3', auth: this.oauth2Client });

const response = await calendar.events.insert({
  calendarId: 'primary',
  requestBody: {
    summary: event.title,
    start: { dateTime: event.startDatetime.toISOString() },
    end: { dateTime: event.endDatetime.toISOString() },
    reminders: {
      useDefault: false,
      overrides: [
        { method: 'popup', minutes: 10080 }, // 7 days
        { method: 'popup', minutes: 4320 },  // 3 days
        { method: 'popup', minutes: 1440 },  // 1 day
      ],
    },
  },
});

const googleEventId = response.data.id;

await this.prisma.calendarEvent.create({
  data: {
    userId,
    courseId: event.courseId,
    type: event.type,
    googleEventId,
    title: event.title,
    startDatetime: event.startDatetime,
    endDatetime: event.endDatetime,
  },
});

return googleEventId;

}
async updateEvent(eventId: string, updates: Partial<calendar_v3.Schema$Event>): Promise<void> {
const calEvent = await this.prisma.calendarEvent.findUnique({
where: { id: eventId },
include: { user: true },
});
if (!calEvent || !calEvent.googleEventId) return;

const integration = await this.prisma.integration.findFirst({
  where: { userId: calEvent.userId, type: 'google_calendar' },
});

this.oauth2Client.setCredentials({
  access_token: integration.accessToken,
  refresh_token: integration.refreshToken,
});

const calendar = google.calendar({ version: 'v3', auth: this.oauth2Client });

await calendar.events.patch({
  calendarId: 'primary',
  eventId: calEvent.googleEventId,
  requestBody: updates,
});

// Update local record
await this.prisma.calendarEvent.update({

3.10 Security & Privacy
3.10.1 Authentication
	JWT tokens with 7-day expiry
	Refresh token mechanism (optional for v1)
	Password hashing: bcrypt with salt rounds ≥10
3.10.2 Authorization
	Role-based: student can only access own data, admin can access admin endpoints
	Implement guards in NestJS or middleware
	All queries filtered by userId from JWT
3.10.3 Data Protection
	Encryption at rest: Integration tokens (access_token, refresh_token) encrypted using AES-256
	Encryption in transit: HTTPS only; enforce HSTS headers
	Rate limiting: 100 requests/minute per user; 1000 requests/minute globally
3.10.4 Privacy
	No tracking of grades or personal data in analytics beyond aggregated metrics
	Admin dashboard shows anonymized user IDs, not names/emails
	Clear privacy policy page
	User can delete account and all associated data

5.1 Critical Rules
	Course codes are REAL HTU codes: Never auto-generate. Use existing curriculum codes or require user input.
	GPA logic lives in GPA service only: No GPA calculations in controllers or UI. Always call GpaService.

	Notes are in-app with Lexical/Tiptap: Not external. No Notion for notes.
	Google Calendar sync is one-way: HTUAI → Calendar only. No reading back.
	Mobile-first always: Design and test on mobile viewport first.
	No placeholders in production: Every feature must be fully implemented. No TODOs in production code.
	Grade badges use exact colors: D=green, M=blue, P=yellow, U=red. Single capital letter only.
	Gamification XP rules are fixed: Use constants from gamification.constants.ts. No arbitrary XP values.
	Admin sees anonymized data: No student names/emails in admin dashboard unless necessary and role-gated.
